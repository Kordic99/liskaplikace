# Updating Liškaplikace

Develop future changes on branch `test` by default. `main` is PROD; merge tested changes into `main` only when the user authorizes promotion. TEST is published at `/liskaplikace/test/`, PROD at `/liskaplikace/`. Both are assembled into one Pages deployment from separate refs. Never send Supabase production configuration to a TEST build or copy real user libraries into TEST automatically. TEST uses isolated localStorage and IndexedDB and has no account login or device synchronization. Do not replace the user's TEST browser storage with fixtures.

Every production release must append a truthful user-facing entry to `app/releases.json` with the next integer ID, Czech title, date and list of changes. Draft notes may change on TEST until published to PROD. Keep all previously published entries unchanged and in ascending order. This history powers each account's cumulative update dialog; never reset users' read markers during a deployment. TEST-only deployments do not require a new production entry.

Run `node tools/check-releases.mjs`, `npm run typecheck`, `npm run test:cloud`, `npm run test:catalog`, `npm run test:releases` and `npm run test:covers` before publishing. CI also requires a new release entry for PROD relative to the last successfully deployed production build. Cover uploads are private, immutable owner-scoped JPEG objects in `book-covers`; retain old objects for backup compatibility. Do not make the bucket public. Backups must include custom cover bytes and restore them into the destination account/local store rather than reuse another user's paths.

Publish the app only to `Kordic99/liskaplikace`. The old `Kordic99/draci-archiv` repository contains a redirect and must not receive app source. Browser configuration keys belong in GitHub Actions variables, not tracked source files.

TEST has an independent browser-local book catalog. Import only explicitly reusable bibliographic data from the official CNB CC0 source; retain source/license receipts in `data/`. Do not import third-party covers, annotations or reviews, add paid APIs/services, or restore Google/Open Library as TEST catalog providers without a new user decision. Keep manual corrections separate from imported fields, catalog backups separate from personal libraries, and run `npm run test:own-catalog` for TEST changes. See `data/README.md`; the shared seed is a bounded sample, not a complete or continuously synchronized catalog.
